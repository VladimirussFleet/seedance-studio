# Seedance Studio

Задача студии — дать Seedance **точную инструкцию движения**: где стоят герои, как они идут, как едет камера, какой объектив, где склейки. Внешность, свет и фактуры Seedance берёт из референс-картинок и промпта. Аниматик отвечает только за движение и композицию.

Студия состоит из двух частей:
- **редактор в браузере** (пользователь сам двигает героев и камеру, ставит ключи, записывает ролик);
- **ты, агент**: собираешь сцену по референсам, правишь `project.json`, проверяешь кадры рендером без окна, пишешь промпт Seedance.

Оба работают с одним файлом. Если ты меняешь `project.json`, открытый редактор подхватывает изменения сам в течение 2 секунд.

## Установка (один раз)

Папка скилла: `~/.claude/skills/seedance-studio/` (Codex: `~/.agents/skills/seedance-studio/`).

```bash
brew install node ffmpeg                         # если нет. Нужен и Google Chrome.
cd ~/.claude/skills/seedance-studio/studio && npm install    # three.js + puppeteer-core, ~55 МБ, Chrome не скачивается
```
Если чего-то не хватает, назови пользователю точную команду установки и дождись, пока он её выполнит.

## Запуск

Проекты лежат в папке `projects/` там, откуда запущен сервер. Рабочая папка пользователя — его текущая папка.

```bash
node ~/.claude/skills/seedance-studio/studio/server.mjs          # откроет http://localhost:5178
```
Запускай сервер в фоне и не останавливай его, пока пользователь работает. При первом запуске в `projects/` появится пример «Пример — встреча на улице».

Рендер без окна (тебе — проверить результат глазами):
```bash
S=~/.claude/skills/seedance-studio/studio
node $S/render.mjs --p="Имя сцены" --sheet                 # раскадровка: 2 кадра на план с подписями -> projects/<имя>/renders/sheet.png
node $S/render.mjs --p="Имя сцены" --stills=0.5,3.2 --labels
node $S/render.mjs --p="Имя сцены" --video                 # чистый MP4 для Seedance
node $S/render.mjs --p="Имя сцены" --video --from=0 --to=15 --out=блок1.mp4
```

## Порядок работы

### 1. Разбор (без кода)
Из истории или промпта пользователя составь таблицу планов: таймкоды `[0-3s]`, кто где стоит и куда идёт, движение камеры и его причина, объектив. Если есть готовый промпт Seedance с таймкодами — бери планы из него один в один. Seedance принимает референс до 15 секунд, поэтому длинную сцену режь на блоки.

### 2. Герои по фото
Для каждого героя из референса:
- Скопируй фото в `projects/<имя>/assets/` и укажи его в `ref` героя.
- **Манекен (по умолчанию, бесплатно):** посмотри на фото и задай `look`: кожа, цвет и тип волос (`short`/`long`/`bun`/`bald`), верх, рукав (`long`/`short`), низ, обувь, телосложение `build` (0.75–1.45), рост `size[1]` в метрах. Цвета бери с фото: Seedance отличит героев по одежде, и в промпте получится честное сопоставление «девушка в красном пальто = @image1».
- **GLB-модель:** если у пользователя есть 3D-модель героя из генератора 3D (Meshy, Tripo, Hunyuan3D, Higgsfield) или подключён такой инструмент, положи `.glb` в `assets/` и создай объект `type: "glb"`. Высота подгоняется под `size[1]` автоматически. Если в модели есть анимации, впиши имя нужной в `glb.clip`.

### 3. Место по фото
- Скопируй фото локации в `assets/` и пропиши `refs.location`. В режиме камеры редактор накладывает его полупрозрачно поверх кадра.
- Собери серый макет: стены, пол, дома, мебель, машины — только то, что влияет на композицию и перекрытия. Размеры реальные, в метрах: этаж 3 м, дверь 2.1 × 0.9 м, стол 0.75 м, машина 4.3 × 1.8 × 1.45 м.
- Если план должен повторять ракурс фото, подбери первый ключ камеры (высота, объектив, точка взгляда), отрендери `--stills` и сравни с фото, потом поправь.
- Декорации делай серыми (`#7e8185`–`#b4b7ba`). Яркий цвет на декорации Seedance может принять за персонажа.

### 4. Движение
- Герои: `keys` с `t` и `pos`. Манекен сам идёт или бежит в зависимости от скорости: шаг считается от пройденного пути, ноги не скользят. Скорость ходьбы 1.2–1.5 м/с, бега от 3 м/с. Ходьбу делай `linear`, а остановку — коротким последним отрезком 0.5–1 с с `out`. `out` или `inOut` на длинном отрезке дают рывок: герой сначала бежит, потом ползёт. Поза (`sit`, `wave`, `point`, `armsUp`, `lie`) задаётся на ключе и держится до следующего ключа.
- Камера: у каждого плана свои `keys` (`pos`, `target`, `lens`). Один ключ — камера стоит. Несколько — камера едет по плавной кривой через все ключи, а `ease` плана задаёт разгон и торможение всего проезда. `shake` 0.01–0.03 — съёмка с рук.
- Приёмы: наезд — 2 ключа к герою; облёт — 3 ключа по дуге, `target` на героя; проводка — путь камеры параллельно пути героя; зум — одна точка и `lens` от 24 до 50; нижний ракурс — камера на высоте 0.3–0.5 м.

### 5. Проверка → показ пользователю
Отрендери `--sheet`, посмотри сам, исправь явные ошибки (герой за краем кадра, камера внутри стены, герои перекрывают друг друга). Потом покажи раскадровку пользователю и скажи, что сцену можно доводить в редакторе: перетаскивать героев, ставить ключи, двигать камеру.

### 6. Запись и промпт
Чистый MP4 — либо из редактора («⏺ Записать для Seedance»), либо через `render.mjs --video`. Версия с подписями нужна только для проверки: подписи модель может перенести в кадр.

Промпт под аниматик:
```
@ref1 — референс движения: повторить путь и скорость камеры, крупность, ракурсы, склейки и перемещения персонажей по @ref1. Внешность, свет и фактуры — из @image1–@image3 и текста.
Девушка в красном в @ref1 — персонаж с @image1. Мужчина в синем — персонаж с @image2. Серые объёмы — [улица старого города], как на @image3.
[0-3s] …видимое действие, причина движения камеры…
[3-6s] …
```
Если в проекте пользователя есть свои правила промптов, они важнее этого шаблона.

## Онлайн-версия (страница в Claude)

Та же студия опубликована как страница-артефакт: ничего не нужно ставить, сцены хранятся в базе страницы.
- Сборка: `studio/build-online.sh` → `studio/dist-online/`, публикуются только свои файлы: index.html, app.js, engine.js, backend-*.js, ai-prompts.js, examples/primer.json. three.js и mp4-muxer страница берёт с cdn.jsdelivr.net.
- Возможности страницы: `{db:{}, user:{}, assets:{}, downloads:true, sample:{images:true}}`. Сначала публикация, потом declare.
- Сцена = документ `projects/<id>` вида `{name, updatedAt, rev, project}`, где `project` — тот же project.json, что в локальной версии.
- Чтобы поменять сцену из чата: прочитай документ (`db_get`, нужна его version), измени `project`, запиши `set` с `ifVersion`, новым случайным `rev` и `updatedAt`. Открытая страница подхватит изменения сама, если у пользователя нет несохранённых правок.
- Фото и модели лежат в файлах страницы: ссылки `blob:<id>` (обычный файл) или `b64:<id>` (GLB, сохранённый текстом). Агент их не создаёт: фото загружает пользователь на странице.
- Кнопки «🪄 Собрать макет по фото» и «🪄 Внешность по фото» вызывают Claude прямо со страницы (тратят лимиты пользователя). Тексты запросов — в `ai-prompts.js`.
- Запись видео идёт в браузере через WebCodecs (H.264), скачивание — через «Скачать MP4». Надёжнее всего работает в Google Chrome.
- Проверить кадры агенту: скачай `project` из базы в `projects/<имя>/project.json` и запусти `render.mjs --sheet`. Фото с `blob:`-ссылками при этом не подгрузятся, макет и герои отрисуются.

## Формат project.json (кратко)

```jsonc
{
  "format": { "w": 1280, "h": 720, "fps": 24 },      // 9:16 — 720×1280
  "duration": 8,                                      // секунды, до 30
  "world": { "sky": "#c3c6ca", "ground": "#8d9094", "grid": true, "fog": [30, 120], "sun": [14, 22, 10] },
  "refs": { "location": "assets/place.jpg", "overlay": 0.4 },
  "objects": [
    { "id": "h1", "name": "Анна", "type": "person", "hero": true, "labelColor": "#ff3b30", "ref": "assets/anna.jpg",
      "size": [0.5, 1.68], "look": { "skin": "#e0b096", "hair": "#2b1d16", "hairStyle": "long", "top": "#b3262b", "sleeves": "long", "bottom": "#1f2430", "shoes": "#141414", "build": 0.9 },
      "keys": [ { "t": 0, "pos": [-0.9, 0, 10], "rot": [0, 180, 0] }, { "t": 4.5, "pos": [-0.6, 0, 3] }, { "t": 5.3, "pos": [-0.5, 0, 2.2], "ease": "out" }, { "t": 6.2, "pos": [-0.5, 0, 2.2], "rot": [0, 138, 0], "pose": "wave" } ] },
    { "id": "w1", "name": "Стена", "type": "box", "size": [6, 3, 0.2], "color": "#b4b7ba", "pos": [0, 0, -4], "rot": [0, 0, 0] },
    { "id": "m1", "name": "Робот", "type": "glb", "hero": true, "glb": { "src": "assets/robot.glb", "clip": "Walk", "rotY": 0 }, "size": [0.6, 1.8], "pos": [2, 0, 0] }
  ],
  "shots": [
    { "id": "s1", "name": "Общий", "from": 0, "to": 3, "ease": "inOut", "shake": 0, "roll": 0,
      "keys": [ { "t": 0, "pos": [0, 10, 36], "target": [0, 1, 2], "lens": 28 }, { "t": 3, "pos": [0, 6.5, 29], "target": [0, 1, 5], "lens": 28 } ] }
  ]
}
```
- Типы: `person`, `glb`, `box`, `plane`, `cyl`, `sphere`, `cone`, `capsule`, `car`, `boat`. Объект стоит основанием на `pos[1]`. «Перёд» объекта смотрит в +Z, `rot[1]` — поворот в градусах.
- `boat` — катер: `size` = [ширина, высота борта, длина], по умолчанию [3, 1.2, 9]. Нос в +Z, ровная палуба на высоте борта (`offset[1]` = высота борта, чтобы стоять на палубе), рубка в передней трети.
- `ease` на ключе описывает, как объект приходит в этот ключ: `linear`, `inOut`, `in`, `out`, `hold`. Отрезки `linear` идут плавной кривой через ключи и не проскакивают за ключ. Отрезок с другой плавностью идёт по прямой. Поэтому повороты и дуги делай ключами `linear`.
- Позы (`pose` на ключе): `auto`, `sit`, `crouch` (присела перед прыжком), `jump` (в полёте), `wave`, `point`, `armsUp`, `lie`.
- Люди, машины, катера и GLB в движении сами разворачиваются по ходу. `"face": "none"` отключает это.
- Все новые поля ниже необязательные: старые сцены открываются как раньше.

### Масштаб, петля, привязки, камера за объектом

```jsonc
{ "id": "car1", "type": "car", "scale": [1, 1, 1],                    // статичный масштаб объекта
  "keys": [ { "t": 12.2, "pos": [0, 4, -0.6] },
            { "t": 12.45, "pos": [0, 4, -0.6], "rot": [-8, 0, 0], "scale": [1, 1.15, 0.55], "ease": "out" } ] }   // смятие «гармошкой»
{ "id": "spanA", "type": "box", "size": [12, 0.8, 15], "pivot": "z-", "pos": [0, 3.2, 7.5],
  "keys": [ { "t": 4, "pos": [0, 3.2, 7.5], "rot": [0, 0, 0] }, { "t": 11, "pos": [0, 3.2, 7.5], "rot": [-38, 0, 0], "ease": "inOut" } ] }
{ "id": "girl", "type": "person", "keys": [ { "t": 0, "pos": [0, 0, 0], "pose": "sit" }, { "t": 7, "pos": [0, 0, 0], "pose": "crouch" } ],
  "attach": [ { "parent": "car1", "from": 0, "to": 9.5, "offset": [0, 0.95, -1.7], "rotY": 0 },
              { "parent": "boat", "from": 11.3, "to": 15, "offset": [0, 1.2, -2.5], "rotY": 180,
                "flight": { "arc": 2.5, "spin": 360, "pose": "jump" } } ] }
{ "id": "s1", "from": 0, "to": 9.5, "follow": "car1", "followYaw": true,
  "keys": [ { "t": 0, "pos": [3.2, 0.7, 0.5], "target": [0, 0.8, 0.5], "lens": 24 } ] }
```
- **Масштаб** `scale: [sx, sy, sz]` — на объекте (статично) и на ключе (анимируется как позиция, с тем же `ease`). Ключ без `scale` берёт масштаб предыдущего ключа. Масштаб считается от основания: сплющенная машина остаётся на дороге.
- **Петля** `pivot`: `center` (по умолчанию), `x-`, `x+`, `z-`, `z+` — `rot` вращает объект вокруг этого края основания (поворот `rot[0]` у моста, ворот, крышки). `pos` по-прежнему центр основания в неповёрнутом состоянии. Знак угла: при `z-` свободный край поднимается при отрицательном `rot[0]`, при `z+` — при положительном.
- **Привязка** `attach`: внутри `[from, to)` объект едет с родителем: мир = преобразование родителя (позиция, поворот, масштаб) × `offset`, плюс поворот `rotY`. Ключи в интервале дают только позу. На краях интервала движок сам ставит неявные ключи — скачков нет. До 3 уровней вложенности (чемоданчик → героиня → машина). Циклы игнорируются. Походка манекена считается относительно родителя: пассажир не шагает.
- **Полёт** `flight` у привязки описывает отрезок перед ней, от прошлого отцепления: по горизонтали линейно, по высоте парабола с верхом `arc` м над прямой, кувырок `spin`° вокруг локальной оси X, поза `pose` на всём полёте.
- **Камера за объектом** `follow` у плана: `pos` и `target` ключей заданы в локальных координатах объекта (Y вверх, Z вперёд по ходу, X — к левому борту, то есть вправо в кадре, когда смотришь объекту в лицо). Мир = позиция объекта + поворот на его курс × смещение. `followYaw: false` — без поворота, только сдвиг. Тряска и завал применяются после.
- Позиция любого объекта в любой момент: `worldTransform(o, t, project)` из `engine.js` (её же используют отрисовка, камера, привязки и подписи).
- Автопроверки движка: `node studio/tests/engine.test.mjs [projects/<имя>/project.json]`.
- Планы идут без промежутков от 0 до `duration`, между ними жёсткая склейка.
- Каждая запись сохраняет предыдущую версию в `project.json.bak`.

## Правила

1. Правки точечные: меняй только то, что назвал пользователь. Один тип правок за заход (камеру отдельно от героев).
2. Кадр зависит только от времени, поэтому любой кадр и план можно перерендерить отдельно.
3. Масштаб реальный, в метрах. Ошибка масштаба = ошибка плана.
4. Прежде чем отдать результат пользователю, посмотри кадры сам (`--sheet`).
5. Не правь `project.json`, пока пользователь двигает что-то в редакторе: попроси его остановиться или работай после сохранения (статус «сохранено ✓»).
6. Не трогай код студии (`engine.js`, `app.js`, `server.mjs`) без явной просьбы.

## Известные ограничения

- Мимики и точных действий руками нет: эмоции, жесты и работу с предметами пиши текстом в промпте по таймкодам.
- Seedance может перенести в картинку серые формы или сетку пола. Помогают явное сопоставление героев с @image, `grid: false` и более детальный макет.
- Мелкие доли секунды Seedance сглаживает, поэтому подгонять аниматик до кадра не нужно.

## Готово, когда

- [ ] План сцены согласован, раскадровка показана.
- [ ] Чистый MP4 нужной длины (≤ 15 с на блок) и формата лежит в `projects/<имя>/renders/`.
- [ ] Каждому герою в промпте сопоставлен @image-референс.
- [ ] Пользователь знает, как открыть сцену в редакторе и перезаписать ролик.
